# Working Style

- Treat me as a peer. Be concise and technical.
- Keep changes focused on the requested task. Avoid unrelated refactors.
- Ask before making consequential decisions when requirements are ambiguous.
- Never delete files or discard existing changes without explicit approval.
- Never install, remove, or upgrade dependencies without explicit approval.
- Read and understand relevant existing code before modifying it.
- Follow existing project conventions unless there is a concrete reason not to.
- Prefer simple solutions over unnecessary abstractions.
- Verify changes when practical. Never claim something was tested or verified when it wasn't.
- Surface meaningful assumptions, risks, and tradeoffs.
